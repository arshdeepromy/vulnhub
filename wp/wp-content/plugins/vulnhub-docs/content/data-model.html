Every application table is prefixed vh_vulnhub_* (the WordPress prefix here is vh_). Core owns the estate tables and creates them with dbDelta in vulnhub-core/includes/class-vh-install.php; satellite plugins own their own tables. This page is the field guide — what each table is for and what its load-bearing columns mean. It is a reference, not a migration script; the install classes are canonical.

Three entities to keep straight. A vuln is a scanner definition (one Tenable plugin, e.g. "RHEL 9 : kernel (RHSA-…)") — it can name many CVEs. An asset is a machine. A finding is one (asset × vuln × port × protocol) — the working row VulnHub counts. There are far more findings than vulns or assets.

The working set

vulnhub_findings — one row per asset × vuln × port

The busiest table (load-tested past 400k rows). Fingerprinted and de-duplicated.

fingerprintsha256(asset_id | vuln_id | port | protocol), UNIQUE — the dedup key.
stateopen, reopened, fixed, archived, suppressed. Only open+reopened are "live" and counted.
severitycritical / high / medium / low / info (info is always suppressed).
risk_scoredecimal — severity × asset criticality × exploit × VPR, capped 100.
exception_id / ticket_idAttached risk-acceptance / remediation ticket (0 = none). A non-zero exception_id removes the finding from live counts.
first_found / last_found / last_fixed / due_atLifecycle timestamps; due_at is the SLA deadline that drives "overdue".
prev_stateThe state before an archive/suppress — the "way back", so a machine returning to service restores exactly.
verification_state / verified_atMirrors ticket verification: pending, confirmed_fixed, still_open, unknown.
bundle_app / bundle_app_slugThe application that ships a vulnerable library, derived from scanner output at write time.
path_zone / zone_pathThe install-path zone of a downloaded/opened component.
scan_uuid / last_synced_atTenable scan id (proves a rescan); "last seen this sync".

Its composite indexes are deliberately ordered for the count queries — e.g. state_sev_risk, exc_state_sev, vuln_state_exc, asset_state_exc.

vulnhub_assets — the merged inventory

One row per machine, merged across Tenable, Intune, Entra, Defender, CMDB and AWS. Highlights by group:

Identity keysprimary_source, tenable_uuid, intune_id, azure_ad_device_id, cmdb_id, defender_id, serial_number, hostname, fqdn, ipv4/ipv4s. sources_json records which system last saw it, and when.
Classificationasset_type (workstation/server/mobile/network/cloud/appliance/unknown), criticality (critical/high/medium/low), environment, business_service, lifecycle_status.
Ownershipowner_person_id, owner_source, owner_confidence (high/medium/low), owner_rule, team_id, location_id.
Coveragecoverage_state, plus per-source timestamps (tenable_last_scan, last_intune_sync, cmdb_last_scan) and Defender columns (defender_onboarding, defender_coverage_state, …).
Roll-upsopen_critical/high/medium/low and risk_score, recomputed by Repo::recalculate_asset_rollups().

vulnhub_vulns — the definition catalogue

UNIQUE on (source, plugin_id). Carries title, family, severity/severity_id, cve_json, the raw scores cvss2_base/cvss3_base/vpr_score, solution, and the product classification columns component_class / product / product_kind / product_slug.

Threat & reachability (owned by vulnhub-threat)

vuln_pathsOne row per definition (PK vuln_id), rebuilt each refresh: route, poc_route, delivery, has_poc, kev, top_epss, top_cve, evidence. The table the attack-path widget reads.
cve_intelOne row per CVE (PK cve_id): the CVSS vector fields, base_score, epss/epss_percentile, kev/kev_added/kev_ransomware, exploit_refs, has_poc, derived route/delivery.
asset_exposureThe internet-facing opinion, kept separate from assets so a connector can't overwrite it: internet_facing, source (rule/manual), basis (evidence/ruled_out/unknown/asserted), reason.
asset_portsObserved listening ports (PK asset+port+protocol) parsed from Tenable's Netstat plugins: remote, service, kind (web/mail/shell/…).

Workflow

tickets / ticket_findingsRemediation tickets (Jira) and their join to findings. Tickets carry status_category (done=closed), verification_state, SLA and routing fields; the join is UNIQUE per (ticket, finding).
exceptionsRisk acceptances: reference (UNIQUE), scope_type (finding/asset/vuln/team), reason, status (draft→pending→approved→…), justification, expires_at, affected_count.
automationsRules that raise tickets on events (trigger_event, conditions_json, actions_json, grouping, throttles).
mapping_rulesOwnership routing: match an asset field, assign a person/team/location/criticality. Distinct from the classification rules below.

Organisation

teamsslug (UNIQUE), manager, Jira routing, and per-severity SLA days (sla_critical_days=7, high=30, medium=90, low=180 by default).
peopleThe directory (UNIQUE per source,source_uid): UPN, email, manager, department, office, team_id, location_id, wp_user_id.
locationsSites: name, slug, city/region/timezone.

Classification & roll-ups

class_rules / class_rule_conditions / class_asset_stateThe asset-classification engine (owned by vulnhub-rules): rules with ordered conditions that set environment/criticality/type/business-service/weight, and the per-asset result.
summary_productsA materialised product-exposure roll-up (assets/findings per product with a stored rank), rebuilt by the dashboard warm job so the "Exposure by product" top-N is an index range, not a live aggregate.
metricsDaily trend snapshots (snapshot_date+metric_key+dimension UNIQUE) — what the trend widget plots.

Bookkeeping & the rest

sync_runsOne row per connector run: mode, status, counters, message, stats_json, log_text.
import_jobsOne row per CSV import: type/shape, resumable byte_offset, status, counters. Never shares rows with sync_runs.
auditWho changed what, when — action, object, summary, actor, IP.
stale_recordsRecords held out of inventory (a name with nothing to act on) — only the importer holds these.
alert_feeds / alerts / alert_matches / alert_eventsThe advisory-watch tables (owned by vulnhub-alerts): sources, normalised advisories, estate matches, and a state-change audit.
aws_accounts / aws_exposureAWS account config and per-instance cloud reachability (owned by vulnhub-aws).
mcp_tokens / backup_jobsMCP API bearer tokens (stored as SHA-256 hashes) and the backup job ledger.

Secrets at rest

Connector credentials never sit in plaintext. Non-secret config goes in an autoloaded option vulnhub_cfg_<connector>; secrets go in a non-autoloaded vulnhub_sec_<connector>, each value encrypted with libsodium XChaCha20-Poly1305 (blobs prefixed vhenc1:). The key comes from the VULNHUB_ENCRYPTION_KEY constant in wp-config.php; if that is absent a fallback key is generated and stored in the database, with a loud admin warning that this is a weaker posture. Submitting a blank secret keeps the existing one.
