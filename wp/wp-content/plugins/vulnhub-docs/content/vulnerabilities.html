The Vulnerabilities screen is the findings list — one row per finding. It is where every dashboard drill-down lands, and every filter it offers is expressible in the URL, so a link can carry an exact query. This page explains the tabs, what each filter selects, and how to read a row.

Findings, not vulnerabilities. Despite the name, each row on the Findings tab is a finding — one vulnerability on one asset. The same vulnerability appearing on 40 machines is 40 rows. To see one vulnerability across every asset, use the Vulnerability on assets tab, or open its detail page with ?vuln=<id>.

Three tabs over the same filters

FindingsOne row per finding. Export CSV (with a column picker) exports the whole filtered set, and the button shows its count.
By productThe products behind the filtered findings, ranked by assets affected. Expand one for "Update X to version Y or later", what that clears, and its outdated assets; Export remediation CSV produces the patch list. See Products & vendors.
Vulnerability on assetsOne row per vulnerability (paged by vulnerability) with exploit and patch chips; expand one for its affected assets and their owners.

The tabs carry every active filter, so switching tabs regroups the same set rather than starting over.

The default view

Out of the box the list shows open findings (open or reopened) on assets in the reporting scope (see lifecycle scoping). Findings covered by an approved exception are still listed, shown dimmed, and there is no control to hide them. A line under the tabs says which estate is being counted, with a link to include every asset. Rows are sorted by risk score until you choose a column.

The controls

SearchFree text — CVE, host, owner, plugin and so on — across the finding, its vulnerability and its asset.
PatchPatch available or No patch available. "No patch available" is the set that needs a decision (a compensating control, an exception or a decommission) rather than a patch window.
Lifecycle supportEnd of life only or In support only (support=eol|insupport). End of life means the operating system or the software itself is discontinued, not that the asset carries one unsupported component.
SeverityA single severity: Critical / High / Medium / Low / Info.
Asset typeWorkstation / server / mobile / network / cloud / appliance.
TeamFindings on assets owned by a team (the Exposure by team drill-down).
DepartmentFindings on devices owned by people in a department (present when the departments plugin is active — see Departments). The Vulnerabilities by department widget drills here, and Export CSV carries it.
AgeBy how long a finding has been open: Under 30 days (new), 30–90 days (mid), Over 90 days (old). The severity-and-age matrix links here.
LifecycleReporting scope (default), Everything with an owner expectation, Every asset, including retired, or a single lifecycle status.
Past SLA onlyOnly findings past their SLA due date (overdue=1; the dashboard's "Past SLA" tile links here).

Apply keeps any URL-only filters you arrived with; Reset clears everything.

URL-only filters

Some filters have no control of their own. They arrive on a link from the dashboard, show a banner saying what they restrict (with a Clear this filter link), and survive Apply:

Statestate — defaults to open_any (open + reopened).
Productproduct=<slug> — every finding for that product (the Exposure by product drill-down).
Routeroute=edge, user or inside — see Routes, delivery & reachability. The edge filter additionally restricts to internet-facing assets and adds a Reachable via column; inside also folds in edge findings on unreachable machines.
Deliverydelivery=email|website|download — within the user route.
Exploitpoc=1 restricts to findings with a working exploit — what the attack-path widget counts.
Zone / platform / not-severityzone (install-path zone, e.g. downloads), platform (windows / linux / macos) and sev_not (exclude a severity) — used by the Downloads-folder widget.
Hostinghosting=<environment> — servers in one hosting environment (the Servers by hosting environment widget).
Assetasset=<id> — every finding on one machine.

Reading a row

Each row shows severity, the vulnerability (expand What the scanner reports for the description, fix and scores, or follow Full detail), the asset, its location, the vulnerable file path, the owner (names are masked until you press the eye in the column header), the due date and any ticket. With route=edge a Reachable via column lists the listening services. The row's Ticket button (raise-ticket permission, no ticket yet) raises one straight away, and Except starts an exception request. Select rows to Export selected or Raise ticket for selected, or select every match across pages. More rows load as you scroll. Sort by severity, vulnerability, asset or due date. See Tickets & exceptions.

The Except button opens the exception request form inside the portal (the Exception register screen renders it in place), so it works for portal-only accounts.

A vulnerability's detail page

?vuln=<id> opens one vulnerability: Scoring (CVSS v3 and v2, VPR, exploit, patch published date, CVEs), Exposure (assets affected, still open, fixed, past SLA), How to fix it, What this is with references, and a paged Affected assets table with its own state filter (open / fixed / any) and export.

Filters compose, and they live in the URL. Because every filter is a query parameter, you can bookmark or share a precise view — "open, exploitable, edge-route findings on servers" is just a link. That is exactly how the dashboard hands you a pre-filtered list when you click a number.
