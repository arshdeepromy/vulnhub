Findings are easiest to act on when grouped by the software that carries them: patch one product across the fleet and many findings close at once. VulnHub classifies every vulnerability into a product and a kind, and the Products and Vendors screens (and the Exposure by product dashboard widget) roll findings up that way.

How a finding is mapped to a product

Tenable ships no clean product identifier on this feed, so VulnHub derives one from the plugin title (with the family as a coarse filter). It stamps four fields on each vulnerability definition:

component_classBroad bucket: os_linux, os_windows or third_party.
product_kindos_package (a Linux package), os_update (a Windows/Microsoft update), library (a component other software bundles), or application (an app in its own right).
productThe human name — "Google Chrome", "Apache Log4j", "Microsoft .NET", or a Linux group like "Linux: RHEL".
product_slugThe URL-safe key used for grouping and filtering (and, incidentally, for the product's icon).

Library vs application matters: a name is treated as a library if it is a known component (libcurl, openssl, sqlite, log4j, glibc, openssh, …) or begins with lib; otherwise it is an application.

Bundled libraries — attributed to the app that ships them

A vulnerable copy of, say, libcurl is rarely something you patch directly — it lives inside an application that shipped it. When VulnHub can read the install path from the scanner output, it attributes the library finding to the application that carries it, and the product roll-up regroups it there. That is why the widget can say "Ships a vulnerable libcurl inside the app — update the app, or check the vendor for a fixed release", and why the product with the most exposure is often an app, not the raw library. (This is exactly the mechanism behind the icons on the Exposure by product widget — each product's slug maps to a bundled logo.)

The Exposure by product widget

Each row is a product, ordered by the number of assets affected (the machines you'd have to touch), with total findings beside it and a proportional bar against the top row. A kind badge marks it as library / app / OS. The list counts open, non-excepted, non-info findings in the reporting scope. Because the top rows move the number fastest, this is the widget to work top-down.

Performance note (for the curious). The product roll-up is materialised into a summary table and cached for six hours, rebuilt when the findings data changes — so the "top products" list is an index lookup, not a live aggregate over hundreds of thousands of rows. If a brand-new deployment shows "No products classified yet", an administrator runs the product classifier once.

Vendors

The Vendors screen groups exposure a level up — by the vendor behind the products — so you can see which supplier relationships carry the most risk across your estate. It is reached from the primary navigation.

Icons

Products show a real brand logo when one is bundled (stored locally under the dashboard plugin's assets/products/<slug>.svg or .png), fall back to a clean single-colour motif for a set of well-known components, and otherwise show a brand-coloured monogram chip. Adding a missing logo is just dropping a correctly-named file into that folder.
