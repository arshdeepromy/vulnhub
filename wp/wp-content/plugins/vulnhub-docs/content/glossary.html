The words VulnHub uses, defined once. Where a term has a deeper page, it is linked.

Core objects

AssetA machine — server, workstation, mobile, network device, cloud instance or appliance. Merged from every system that knows about it into one record.
Vulnerability (vuln)A scanner definition — one Tenable plugin, e.g. "RHEL 9 : kernel (RHSA-…)". A single definition can name many CVEs.
FindingOne vulnerability on one asset (per port/protocol). The unit VulnHub counts. Far more numerous than assets or vulns.
CVEA single catalogued vulnerability identifier (e.g. CVE-2024-1234). A vuln definition rolls up one or more CVEs.
TicketA remediation task, tracked in Jira, linked to one or more findings.
ExceptionA formally accepted risk — a decision, with a reason and an expiry, that removes findings from the counts. See lifecycle.

Finding states

open / reopenedCurrently detected (reopened = was fixed, then seen again). The only "live" states — everything counts these.
fixedA scan no longer reports it. Closed; outside the counts.
suppressedInformational severity — parked outside every count on purpose.
archivedIts asset left service; set aside, restorable if the machine returns.

Severity & scoring

SeverityCritical / High / Medium / Low / Info — the scanner's category. Info is always suppressed.
CVSSThe industry 0–10 score. Its vector (attack vector, privileges, user interaction) is what VulnHub uses to place a finding on an attack route.
VPRTenable's Vulnerability Priority Rating — a 0–10 priority blending CVSS with threat intel. Feeds the risk score.
EPSSFIRST's probability (0–1) that a CVE will be exploited in the next 30 days. Threshold default 0.10. See scoring.
KEVCISA's Known Exploited Vulnerabilities list — "being exploited in the wild right now". The highest-trust exploit signal.
Risk scoreVulnHub's single 0–100 prioritisation number: severity × asset criticality × exploit × VPR.
has_poc / exploitableA working exploit is plausible — the CVE is on KEV, has published exploit code, or is over the EPSS threshold.

Attack path

edgeReachable straight from the internet — no account, no click — on an internet-facing machine.
userDelivered to a person who opens it, via email, website or download.
insideOnly usable once somebody already has a foothold (privilege escalation, lateral movement).
deliveryWithin the user route: mail / web / file — how it reaches the person.
ReachabilityWhether the internet can reach a machine: Reachable (observed evidence), Ruled out (scanned, nothing listening), or Never looked (no port scan yet). See classification.

Estate & coverage

Reportable / in serviceThe default lifecycle scope: live and unknown-status machines someone can act on. See lifecycle scoping.
Coverage gapAn asset a system knows about that Tenable (or Defender) has no current record of — a scanning blind spot.
Owner / team / locationWho is accountable for an asset. Resolved by ownership mapping from Intune/CMDB signals.
CriticalityHow much a machine matters (critical/high/medium/low) — multiplies risk.
Component class / product kindWhether a finding is an OS package, OS update, a library or an application. Drives the product roll-ups.

Plumbing

ConnectorA plugin that ingests from an external system (Tenable, Intune, CMDB, AWS). See data sources.
Sync runOne execution of a connector, recorded with counts and a log under Admin → Sync activity.
WidgetOne card on the dashboard. Registered by a plugin, cached, and (usually) exportable.
PortalThe front-end application you are in — as opposed to WordPress's own wp-admin.
